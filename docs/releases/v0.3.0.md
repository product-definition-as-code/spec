## Legacy v0.2.0 regression and erratum

The immutable tag `v0.2.0`, commit `5faef0ede79e141fd9e16856dd35c747d2385ebb`, was executed separately with serialization v1alpha1 and published runner 1.0.1. Result: **43/44 pass**, one failure, zero skips or errors. [Complete unmodified tagged result](v0.3.0-evidence/v020-tag/conformance.json).

The sole failure is `configuration-unknown-key`: that tag expects `field: tooling`, while the implementation emits `field: /tooling`. RFC 0085, already included in v0.2.0, requires an RFC 6901 JSON Pointer. The fixture expectation was corrected before this release in the existing v0.2 contract maintenance revision. The old tag is not changed, no diagnostic is filtered, and the raw result is not relabelled as a pass. This is a known fixture erratum, not a reason to regress the implementation to a nonconforming diagnostic.

The corrected v0.2 profile is pinned at `b3f44d2179a58bbee0478fae517ab75f3249ca39`, the same revision as ProductShape's existing legacy CI. It passes **45/45 cases and 12/12 digest pins**, with zero failures, errors or skips. Removing citation verification makes 11 cases fail as expected, proving citation coverage is exercised. Its separate result and negative citation control are retained under [v020-corrected](v0.3.0-evidence/v020-corrected/). It includes the later optional-journey case, so its total is 45 rather than the tagged 44.

## Reproduce

Use Node 24 and pnpm 11.1.0. Check out the exact spec, runner and ProductShape revisions listed above into separate directories. Build the runner with a frozen lockfile. Install the implementation outside the ProductShape source tree:

```sh
mkdir toolchain artifacts reports
npm pack @prodshape/cli@0.26.1 --pack-destination artifacts
npm install --prefix toolchain --ignore-scripts --save-exact \
  ./artifacts/prodshape-cli-0.26.1.tgz pdac-conformance@1.1.0
sha256sum artifacts/prodshape-cli-0.26.1.tgz
node productshape/src/scripts/verify-v030-conformance.mjs \
  --cli "$PWD/toolchain/node_modules/@prodshape/cli/dist/bin.js" \
  --runner "$PWD/toolchain/node_modules/pdac-conformance/dist/bin.js" \
  --spec "$PWD/spec" --tarball "$PWD/artifacts/prodshape-cli-0.26.1.tgz" \
  --reports "$PWD/reports"
```

The initial run used the runner bundle built from the pinned source while its protected npm publication awaited approval. The reproduction above uses the published runner. Keep source-run and registry-run evidence distinct.

For legacy runs, use `productshape/src/scripts/verify-pdac-conformance.mjs` with published runner 1.0.1, the selected spec SHA, the installed package and its tarball. The harness retains the positive result, digest audit and a negative control that removes citation verification. The immutable tagged erratum causes that run to exit 1; inspect the complete report rather than ignoring the exit.

Run `python scripts/check-v030.py`, `python scripts/test-migration.py`, `node scripts/check-templates.mjs` and `node --test scripts/check-templates.test.mjs` in the spec checkout. Python dependencies are pinned in `scripts/requirements.txt`.

## Publication and public coherence

The [release manifest](../../release.json) binds the method, serialization, tooling versions and evidence. `node scripts/check-release.mjs` checks all named cases, observed provenance, zero skips and public version declarations; its self-test rejects missing cases and mismatched pairs. `node scripts/check-release.mjs --published` additionally checks npm, the official non-prerelease GitHub release and the deployed site's manifest. The website consumes this manifest from the normative repository rather than inferring a version with a fallback.

Publication order: runner 1.1.0 through its protected CI environment; specification release PR and official v0.3.0 tag/release; website and organization profile release references; live verification. ProductShape 0.26.1 already ships the qualified implementation, so no replacement implementation package is needed. `pdac-lint@1.0.0` is an existing forwarding transition package in the runner repository; the old repository URL redirects there. No new lint compatibility release is required or planned.

## Limits

All 147 published v0.3 cases ran, including lifecycle validation, one-hop accounting, gate ordering, affected citations and explicit evidence operations. Other planned cases in the [conformance inventory](../../conformance/README.md) remain outside the executable suite. Structural validity, digest identity and adapter reports do not authenticate external outcomes or prove semantic truth. There is no second independent full implementation; [v1 maturity gates](../../MATURITY.md) remain open.

Migration of an adopter's active overlays and consumer pins requires explicit review; the baseline helper does not silently migrate them. See the [migration guide](../migrations/v0.3.0.md).
