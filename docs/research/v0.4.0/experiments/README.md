## Source intent and representation

[Draft PDaC artifacts](intent/) reuse the existing `conformance/cases/lifecycle-valid` shape and the room-booking vocabulary/60-day idea in the released templates. Their draft policy says one indivisible slot, positive integer capacity, whole-day lead time, atomic confirmation/cancellation/expiry and fixed identity; negative lead times are excluded as an **additional declared research assumption**. No owner product policy is accepted by creating this fixture.

Human/agent semantic work: choosing integer abstraction, excluded negative times, atomicity, identity trust, guard/effect formulas and per-property dependencies. These were handwritten interpretations, **not a normative translation of v0.3.0**. The source fixture and formal model are research inputs with explicitly separate roles, not two new canonical product authorities. Contradictions and mutations are deliberately labelled alternatives. The current predicate meanings in [booking.smt2](models/booking.smt2) use `0=REQUESTED`, `1=CONFIRMED`, `2=CANCELLED`, `3=EXPIRED`; `Inv` is positive capacity, bounded used slots and confirmed implies at least one occupied slot. The checked confirmation guard requires REQUESTED, nonnegative lead at most 60 and free capacity; confirm adds one, cancel/expiry subtract one only from CONFIRMED.

[Expectations](expectations.json) freeze each public query's expected status before execution. [booking.dfy](models/booking.dfy) restates two arithmetic effects as implementation contracts. This restatement is manually reviewed correspondence work; a tool does not infer its fidelity from the prose. In particular, that Dafny example does not yet encode the lifecycle state or lead-time rule.

[Evolution script](evolution.py) uses real draft v1alpha2 frontmatter, private Git baseline revisions and complete proposed target files for five changes. It commits unaccepted research snapshots, **not approval/apply**; one-hop unaffected accounting remains pending, so schema validity is not full Product Change conformance. Stage changes accumulate for digest comparisons, while each SMT delta query isolates its labelled semantic change; that distinction is in the JSON. All original pins/results are retained. A manual dependency list is external experimental metadata; it does not alter the normative graph or citation scope.

## Commands and raw evidence

Requirements: Linux x86_64/glibc compatible with the pinned distributions, Java 21, Python 3 with the repository's [requirements](../../../../scripts/requirements.txt), Git and an existing user systemd manager supporting cgroups. This is the observed environment, not a cross-platform claim. No global install or container/paid runner is needed.

```sh
python3 docs/research/v0.4.0/experiments/install-tools.py /tmp/pdac-v040-tools
python3 docs/research/v0.4.0/experiments/reproduce.py /tmp/pdac-v040-tools /tmp/pdac-v040-reproduction-new
```

The output directory must be new: reproduction never overwrites earlier results. Runner timeout/launch errors retain classified receipts and partial output; scoped cleanup addresses only that job. Failure-path checks: `python3 docs/research/v0.4.0/experiments/test_runner.py`. Installer uses exact asset hashes; interrupted/mismatched downloads stop without automatic retry. [Candidate metadata](../calibration/tool-candidates.json) pins source commits and publisher digests. Alloy's jar SHA-256 is the observed `6b8c1cb5bc93bedfc7c61435c4e1ab6e688a242dc702a394628d9a9801edb78d`, **not a publisher-attested digest**.

Each [run record](results/) contains the exact command, systemd containment command, platform, wall latency, exit code and stdout/stderr hashes, with raw proof/counterexample output. Reproduction records also include input hashes. Service limits: 30 seconds, 2 GiB aggregate memory, no swap, 64 tasks, entire descendant group killed on timeout; Java heap 1 GiB; Dafny one core and 20-second internal verification limit. One job at a time; zero automatic retries. Python checks the saved concrete witnesses and finite cycle; it is not an independent checker of every SMT proof certificate. Resource output in the reproduction receipt confirms the cgroup values. LLM calls made by these scripts: **zero**. Coordination/model authoring used an agent; actual usage/cost metering unavailable, not zero and not blocking.

### Preserved failures and correction

- `alloy-help`: `exec --help` is unsupported; the CLI returned usage with exit 1. The usage supplied the working `exec -q -t json -o ...` command; no hidden repair loop.
- `booking-v1.smt2` and `z3-booking`/`cvc5-booking` raw outputs preserve the initial encoding defect: the two Structured Behaviour probes omitted `nextState=CONFIRMED`. The model returned state 0. `booking-v2.smt2` adds that missing conjunct; `*-booking-corrected` files preserve that separate run. Matching expected `sat` statuses alone had not detected this fidelity error. The old run commands name the file before correction; versioned model files preserve their original bytes.
- Independent scientific review SCI-01 found the same partial-state issue in three other mutation probes. Current `booking.smt2` (v3) constrains confirmation mutants to state 1 and double-release mutant to state 3; `*-booking-v3` and state-aware witness assertions preserve the correction separately. Arithmetic results were valid earlier, but the full returned valuations did not represent the labelled transitions.
- Initial Dafny runs used the bundled default backend without recording the selected backend. The subsequent `dafny-booking-pinned` run explicitly selects bundled Z3 4.12.1; reproduction also pins it for feasibility. Do not infer the original default backend from this later pin.
- Methodology review M2 found an unobserved outer-timeout/launch-error path that lost its receipt. The runner now preserves that evidence and records scoped cleanup; two mocked tests cover the failure paths. No actual outer timeout is claimed.
- Negative Dafny diagnostics and resource-limited `unknown` are intentional observations, retained separately from tool/encoding errors.

## What this says about PDaC

Deterministic execution can validate structure, traverse declared dependencies, detect stale bytes, generate obligations from an **explicitly supplied encoding**, call formal tools, validate concrete arithmetic/graph counterexamples and reproduce logs. None of these steps needs an LLM. Natural-language interpretation, authority selection, completeness of formalization/dependency discovery and acceptance of business assumptions remain semantic judgments; formal checks can expose mistakes but cannot approve product decisions.

These results support continuing **external tools with unchanged v0.3.0**. They do not measure a distinctive PDaC benefit or justify new schema fields, native semantics or a formal language. Potential research value is governed property/assumption lineage and review after changes; existing files, citations and external manifests may already suffice. H0–H5 and authority/architecture choices remain open. Public examples are excluded from future held-out scoring; independent reviewers/evaluators and frozen cohort controls are still necessary for comparative claims.
