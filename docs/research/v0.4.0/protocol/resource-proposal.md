# Execution safeguards and evaluation planning

Owner correction at G1 authorizes exploratory technical execution, calibration and documentary review using existing environments, tools and subscriptions. **No monetary/token ceilings, billing verification or LLM metering prerequisites.** Do not purchase services or provision paid infrastructure. Missing consumption data is unknown, not zero, and never blocks research.

## Exploration versus scored evaluation

Coordinator executes small public models and ordinary bounded corrections. Use one tool job at a time, 30-second wall time, 2 GiB aggregate memory and 64 tasks per systemd job, killing descendants on timeout. Keep failed attempts and explicit corrected versions; no automatic retry loops. Installation and syntax/help inspection are ordinary research commands. The earlier four-check plan is an initial sample, not a prohibition on investigating defects or subsequent models.

Agent sessions may interpret/propose encodings and analyze results. Solvers, verifiers, model checkers, parsers, graph algorithms, hash checks and deterministic experiment runners perform computational checks. LLM judgment never substitutes for proof. Investigate the entire reproducible path with no inference calls; independently review semantic correspondence rather than assume it from solver success.

Record commands, actual versions/assets, environment, inputs, output, assumptions, limitations and elapsed time. Record tokens/costs when available; their absence does not block execution. Do not claim cost superiority without adequate observations. Human review, context reconstruction and verification latency remain meaningful evaluation measures.

## Future matched pilot — still not authorized

The existing 64 authoring/eight evaluator-session design is a candidate maximum task layout, not a committed experiment. Reduce it using technical findings. Before scored comparisons freeze intent, tool/model identities, fair treatment allocation, seed/order, held-out custody, eligible faults, thresholds, responsibility and technical query/run limits. Independent evaluation remains required for comparative claims. No money/token cutoff or usage-metering field is an entry criterion.

Exploratory examples are public and ineligible as held-out evidence. Do not modify a scored design after outcomes to obtain preferred support. Routine documentary/prototype fixes need no further permission; record corrections without erasing failures. Escalate material product decisions, unavailable dependencies, security concerns, paid infrastructure needs or normative-contract changes. No autonomous later phase, production features, releases or normative RFCs.
