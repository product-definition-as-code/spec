## Product, treatments and schedule

[Proposed intent](product-intent.md) supplies every accepted/rejected behaviour, identity/time/unit assumption and complete change sequence; [snapshots](intent.json), [tasks](tasks.json) and public examples are immutable inputs. Eight episodes, four cohorts, two schedules (17,29): **64 fresh author sessions**. Cohorts: C1 ordinary requirements without formal verification; C2 released PDaC without formal verification; C3 competent ordinary requirements/traceability with formal verification; C4 PDaC with exactly the same formal stack. Primary contrast C4/C3. Two schedules repeat trajectories, not independently sampled populations or deterministic model seeds. Counterbalance cohort order and rotate within each episode; the exact plan is generated and hashed before approval.

All authors receive identical current intent/examples/requests and their own complete predecessor files/Git history, no future changes or other cohorts. They may retain structured notes, stable prose IDs, dependencies, assumptions and change logs; C3 is not a deliberately weak control. PDaC cohorts alone receive the released chapters and ProductShape, and must execute real changes. Method instructions/representation and formal-tool access are intended treatments; additional context and governance effort are counted, not hidden. Current-only prose is rendered literally from the same approved template. Public files containing future episodes never enter author mounts. No reference oracle/formulas are supplied. New sessions inherit no conversation or agent memory; predecessor artifacts provide continuity.

## Fixed interfaces and computational scope

All cohorts create a pure executable product decision model `decision.py`, not production implementation. C3/4 additionally author ordinary QF_LIA SMT-LIB `Step` contracts, with the same explicit [interface](INTERFACE.md). They derive their own semantics, assumptions, obligations, checks and findings; no custom PDaC language/schema is introduced. Author proof claims require recorded solver input/output; LLM judgments never count as proof. Evaluation queries compare expected relation membership and exclude alternative outputs **for each finite typed held-out input**, not universal executable/formal correspondence. Malformed JSON shape/type cases test Python only and are never misrepresented as SMT-sort proofs. Author-model correctness beyond these checks remains unproved.

One session per episode, no automatic repair/retry. Block that trajectory if core outputs are missing, inputs changed, status is blocked, unresolved decisions remain, a PDaC change/apply is absent, old accepted changes are edited or structural validation fails. This is an automatic handoff check, not human product acceptance or certification that the report is truthful. Preserve failed/blocked attempts in denominators; continue other independent trajectories. Current intent is owner-approved at G1; approval statuses inside test Product Changes remain synthetic workflow fixtures. Do not fabricate human change approvals.

## Roles, isolation and evaluation

- **Coordinator (this Codex session):** packet preparation, dispatch, immutable attempts, integrity checks, bounded repairs before freeze, GitHub reporting. Has read public inputs only, no private cases; cannot adjudicate its own work as independent human intent validation.
- **Intent designer:** fresh session `/root/intent_designer`; public policy author, excluded from independent evaluation.
- **Custodian/evaluator:** separate `/root/heldout_custodian` session, private oracle/cases and qualification. Public [custody commitments](custody.json), [exposure/limitations](custody.md). Two disjoint schedules, **1,164** cases total, no exact public-case overlap. Private controls: 48 eligible deviations, eight equivalent and eight invalid; these are controls, **not an executed mutation campaign or author-detection score**.
- **Scorer implementer:** `/root/evaluation_infrastructure`, no private case access; deterministic scoring code/public tests.
- **Protocol reviewer:** fresh `/root/protocol_independent_review`, public protocol/control review, no private cases/author dialogue.
- **Post-output evaluators:** eight new isolated documentary sessions (one cohort/schedule trajectory each), distinct from every author/designer. An additional fresh synthesis reviewer checks paired comparisons and classifications before G2. They review documentary continuity/assumptions against approved intent and machine receipts; semantic judgments are labelled agent assessments, never mathematical verification. Record actual identities/exposure/unblinding and disagreements. Root orchestrates these automatically, without asking owner to recruit or organize anyone.

Requested author model **gpt-6.1-sol**, medium reasoning, local Codex CLI **0.172.0**. Serving weights/provider revision are opaque; pin request, client version/launcher hash and actual event metadata, disclose alias drift. All authors use identical settings. Fresh contexts/same provider/host are not independent human expert or independent organizational validation. Artifact representation may defeat evaluator blinding. Mount namespaces hide host home/repositories, custody, other cohorts and prior conversations. Same-host administrators and coordinator permissions remain a trust boundary. No web search, external service use or paid provisioning by authors.

Author sessions mount only their trajectory and a clean authentication directory using the existing subscription; global configuration/skills/plugins are not loaded. Formal tools and ProductShape are host gateways: author requests get pinned execution, host-owned receipts and write-ahead budget reservations. Solver namespaces see only the current input read-only and empty scratch; they cannot overwrite receipts. All host tool jobs are globally serialized. Closing an author drains active work and cancels queued requests. Submitted Python evaluation runs in a no-network namespace with only its source, cases and trusted worker. Pin submissions before custodian access; do not return held-out feedback to authors or rerun after results. Custodian releases private material only after the scored evaluation/review and owner publication decision.

## Predeclared outcomes and explicit endpoint amendment

This small pilot proposes **finite case discrepancy** as primary C4/C3 screening endpoint: an executable disagreement **or**, where applicable, SMT disagreement with the approved oracle. Count once per case; show executable/formal panels separately. Known error dominates unknown. Primary benefit uses the lower bound `C3 known discrepancies/N − C4 (known discrepancies + unknown)/N`; an unknown baseline alone cannot demonstrate benefit. Timeout/missing/invalid input to evaluation is unknown, never correct. Report eligible denominator, known-discrepancy rate and conservative rate counting unknown as discrepancy; retain blocked trajectories as unknown for every assigned case. Pair cohort differences by schedule and episode; report ranges/dependence, no unsupported p-value or power claim.

**Proposed screening margin: at least 10 percentage points lower discrepancy in C4 than C3 in each schedule under the conservative comparison, with zero additional rejection of approved valid behaviours in either executable/formal panel.** Publish 5/10/15-point sensitivity, every class and both schedules; no selecting whichever panel favours H0. This is a proposed **amendment of endpoint**, not evidence on the original eligible-mutant-fault detection endpoint. The original fault-detection rate and 20% human review-time benefit route remain **unmeasured**, not silently replaced by case accuracy or agent estimates. Owner explicitly approves this narrower screen before outcomes. It can recommend further work, not establish general H0 benefit, H3 detection or a normative extension.

Agent documentary review separately distinguishes structural impact, citation freshness, declared semantic dependencies, mathematical validity and current-intent applicability. Record source pins/history; absence of a dependency audit means completeness unknown. Preserve old evidence; do not renew pins automatically. B5/B6 decision equality cannot prove documentary freshness or equivalence. H4/runtime implementation correspondence remains phase 3. Findings taxonomy: invalid experiment, correctable defect, failed verification, inconclusive, evidence against hypothesis/architecture/extension separately. No product decision or assurance claim may be silently invented.

Collect CLI tokens when exposed, wall time, tool latency, method-context bytes, actual calls, retries, output/history sizes and available reconstruction/human attention. Token/billing absence is unknown and never blocks execution. Self-reported reconstruction time is a proxy, not measured human review. No cost superiority if relevant observations are missing. Pre-freeze ordinary corrections are recorded; after freeze preserve failures, no outcome-driven amendments/retries or fresh-case regeneration.

## Fixed technical limits

- At most two active authors; **480 seconds, 4 GiB, no swap, 128 tasks** each; zero automatic author retries.
- One host tool job globally: **30 seconds, 2 GiB, no swap, 64 tasks**. Maximum author-solvers **64 processes/2,048 queries per formal session**: aggregate **2,048 processes/65,536 queries** over 32 C3/4 sessions. Failed/reserved jobs consume limits. ProductShape **64 author calls plus one post-author validation** per PDaC session, aggregate at most 2,080 calls. Host-owned ledgers, no direct solver/package mount to authors.
- Independent deterministic evaluation: at most **64 solver batches / 7,776 queries**, plus at most 64 Python worker batches under the same 30-second/2-GiB job safeguards. Cases contain schedule fields; count applies once per relevant submission. Persistent locked aggregate ledger reserves before launch and cannot reset caps. One scored invocation, new output directory; no automatic retry.
- Documentary evaluators: eight plus one synthesis session, **480 seconds/4 GiB each**, no automatic retries, no solver scoring by LLM. One at a time after outputs freeze. Failure/inconclusiveness is reportable and does not prompt unlimited replacement reviewers.
- No monetary/token ceiling, billing check, subscription purchase or paid infrastructure. Stop only at a substantive unresolved product decision, containment/security/dependency failure, paid-resource need, frozen cap or existing gate. Post-G1 execute #131–134 and report G2; no automatic phase 3 or normative work.

No further routine intervention is planned.
