**Disposition: native allowlist is a plausible substitute for tool confinement, but the supplied canary is insufficient to clear a scored run.** Material unresolved points:

1. **Trusted launcher boundary expands unless separately contained.** The original outer namespace confines the Codex CLI itself to public work, authentication and runtime mounts. Native tool sandboxing confines spawned tools, while the unsandboxed CLI can see the host filesystem/network. The CLI was already trusted with auth, but that is not identical to being trusted with every host repository, private evaluation path and conversation store. Document this precise change; demonstrate that clean startup/context construction cannot ingest host instructions, configuration, plugins, history or private sources. If the requirement is equivalent confinement of the CLI process itself, native-tool-only isolation does not satisfy it. Do not describe the trust boundary as unchanged.

2. **Qualify the actual dispatch path and every required computational path.** Check-4 invokes `codex sandbox`, not the `codex exec` configuration that will generate tools. Require the actual launcher's effective permission policy to match the canary, with no escalation/unrestricted tool path. Existing code still uses outer `bwrap` for packet Git, solver/method gateways and final validation; qualifying author tools alone does not establish those work under AppArmor. Run deterministic public transport checks for every required path, including independent execution/scoring confinement, without reading private cases. Record exact commands, enforced policy, pinned executable and receipts. Fail closed rather than silently fall back.

3. **Socket exceptions and read-only evidence are untested in supplied evidence.** With network disabled, prove own solver/method socket round trips work and another session's socket plus unrelated host Unix sockets do not. Prove exception grants do not make socket parents or receipt directories readable/writable. Exercise review mounts: read evidence, deny edits/deletions/replacements/renames through writable ancestors, write only assessment output; check symlink traversal. Use existing public sentinels with known contents outside the allowlist, not nonexistent paths: the current canary accepts FileNotFoundError as a denial and cannot by itself distinguish these cases. Auth denial should cover the actual ephemeral auth location as well as the normal host auth path. Do not probe real held-out paths further.

Before a scored run, the deterministic checks must also verify resource enforcement/descendant cleanup and that tools cannot read another same-UID process's environment/files via `/proc` or inherited descriptors. These are concrete channels re-exposed by removing the outer PID/mount namespace. Check only synthetic sentinel processes and public files. Confirm that minimal runtime access and inherited environment expose no direct pinned solver/package bypass or credentials. The prior protocol already trusts host administrators; this does not require defending against the administrator.

Comparability: use one revised, frozen launcher/policy for every author and documentary evaluator, retain CLI 0.172.0/model/effort, ordering, cohort contexts, gateways, budgets and stopping rules. Record the isolation change, new source/manifest pins and public qualification receipts before any new outcome. Keep attempt1 invalid and separate; do not pool its failed authoring with the renewed comparison or retry trajectories selectively. Tool confinement changes are not a treatment if applied uniformly, but altered available paths, runtime tools, environment or context loading can become cohort confounders. Retain original endpoint/custody/evaluator separation and all negative/unknown outcomes. No evidence here establishes unchanged evaluator independence or held-out confidentiality beyond the specific checked channels.
